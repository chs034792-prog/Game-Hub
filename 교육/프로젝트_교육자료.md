**공통점 (모든 게임에 해당)**
- **HTML 파일 하나**로 돌아간다. 엔진·빌드 도구·외부 라이브러리 없음. 브라우저로 열면 바로 실행.
- 수치(밸런스)는 파일 **위쪽 데이터 표**(`const 대문자 = ...`)에 모여 있다. 콘텐츠 추가는 대개 "표에 한 줄 넣기 + 그 효과 코드"다.
- 저장은 브라우저 `localStorage`. `file://`로 열면 저장이 막힐 수 있으니 확인은 `python -m http.server` → `localhost:8000`.
- 원본 4개 폴더는 **각각 별도 git 저장소**(GitHub `chs034792-prog/<이름>`). 허브의 `games/*.html`은 사본이다 → `../CLAUDE.md` "코드 규칙".
- 휴대폰(GitHub Pages)으로도 플레이한다. 화면을 바꾸면 **모바일 폭에서도 확인**한다.

## 2. 게임별 소개

### 🟢 슬라임 키우기 (`SlimeGame/`)

**한 줄**: 슬라임을 때려 젤리를 모으고, 먹여서 레벨을 올리고, 몬스터를 잡으며 더 깊은 층으로 내려가는 방치형 게임.

- **핵심 순환**: 젤리 → 강화(힘 훈련·장비) → 사냥 가속 → 더 깊은 층 → 더 큰 젤리 / 젤리 → 먹이 → 레벨 → 체력·스킬 해금.
- **시스템**: 클릭 획득(초당 10회 상한), 자동 수익(젤리밭), 지수 비용 업그레이드 9종, 장비 3칸(무기 10·방어구 7·장신구 6), 액티브 스킬 3개(Lv 15/30/45), 업적 20, 보스(10층마다), 오프라인 보상(8시간, 최대 48시간), 환생(Lv 20 이상 → 영혼) + 영혼 강화 7종. 몬스터 30종 × 등급 8.
- **데이터 표**: `UPGRADES`, `SOUL_UPGRADES`, `WEAPONS`, `ARMORS`, `TRINKETS`, `SKILLS`, `ACHIEVEMENTS`, `MONSTERS`, `TIERS`, `BOSS_*`.
- **꼭 알아둘 설계 결정**
  - **사냥 보상에는 레벨 배율·영혼 배율을 걸지 않는다.** 둘 다 걸면 "젤리 → 레벨 → 더 큰 보상" 고리가 닫혀 수치가 폭발한다(시뮬레이션에서 4시간 만에 층 44,640). 이 고리를 다시 잇는 변경은 하지 않는다.
  - 레벨업으로는 공격력이 오르지 않는다 (2026-09-03 결정).
  - 몬스터 전투에 제한 시간이 없다 (README "제한 시간을 없앤 이유").
  - 연출과 게임 로직은 분리되어 있다.
- **README 의 "다음에 할 일"**: 업그레이드 추가, 오프라인 보상 상한 판매, 숫자가 1e308 을 넘으면 큰 수 처리.

### 🔷 넥서스 디펜스 (`Nexus-Defense/`)

**한 줄**: 화면 가운데 넥서스를 사방에서 몰려오는 적으로부터 지키는 디펜스. 가장 오래, 가장 크게 키운 게임.

- **진행**: 웨이브가 끝없이 오른다. 판 안에서는 **골드**로 강화, 판이 끝나면 도달 웨이브만큼 **코어**(영구 재화)를 받아 영구 강화. **특수 코어**는 영웅 직업 변경용.
- **지역 17곳**: 초원(1~100) → 숲 → 산 → … → 태양(1001) → 은하 → … → 종말의 끝(2201~2500). 앞 지역을 클리어하고 코어로 해금하면 그 지역부터 출격.
- **유닛**: 영웅(전사·궁수·마법사, 전직, 200웨이브 클리어 + 8,000 코어로 해금), 병력(지상·기갑·공중 각 I~III 단계). 넥서스 진화(100웨이브), 테크트리, 코어 복권.
- **부가 기능**: 이어하기, 백업 코드(기기 간 이전), **온라인 랭킹(Supabase)**, 쿠폰 코드, 운영자 모드 `?dev=1`(코어·골드 무제한, 웨이브 이동 — 실제 기록은 오염되지 않게 막아 둠).
- **데이터 표**: "밸런스 데이터" 구역의 `CFG`, `HEROES`, `HERO_CLASSES`, `HERO_ADV`, `GROUND_UNITS`/`MECH_UNITS`/`AIR_UNITS`, `TROOP_TIERS`, `ENEMIES`, `ZONES`, `TIERS` 등. 새 적은 `ENEMY_ART_NAMES`에도 이름을 넣어야 모습이 정해진다.
- **대표님이 원하는 방향 (반복 요청)**
  - **스킬 해금 레벨은 높게.** 새 스킬을 기존보다 낮은 레벨에 두지 않는다.
  - 영웅은 장기적으로 **Lv 1500 이상**까지 오르고, Lv 1500 영웅은 가장 강한 병력보다 강해야 한다 (경험치 곡선은 제곱형으로 완만하게).
  - 병력은 **상위 티어가 하위 티어보다 확실히 세게**. 수치를 바꾸면 DPS 비교표로 근거를 보인다.
  - 목표 레벨·수치를 들으면, 지금 규칙으로 **실제로 도달 가능한지 먼저 확인**한다.
- **주의**: 온라인 랭킹 접속 설정(Supabase)은 건드리지 않는다. 화면 색·모양은 디자인 토큰 하나로 묶여 있다(2026-09-23) — 아트팀은 그 토큰을 기준으로 제안한다.

### 💰 머니 디펜스 (`Money-Defense/`)

**한 줄**: 워크래프트3 유즈맵 **'돈타워' 초기 버전**을 옮기고 콘텐츠를 약 4배로 늘린 경로형 타워 디펜스. 라운드는 끝없이 이어진다.

- **핵심 규칙**: 일용직 노동자(죽지 않음, 최대 6명)가 타워를 짓는다. **돈타워는 몹이 아니라 노동자를 때려서 돈을 번다.** 학교 타워(놀이방 → 대학교), 옵션타워 11계열 × 5단, 돈벌이 건물(로또 회사·은행·부동산), 유지비, 연구소 연구 체인.
- **게임 오버 없음**: 필드 몹이 난이도별 한도를 넘으면 라운드가 멈추는 '성 지키기'식.
- **콘텐츠**: 난이도 5(하수~하드코어), 몹 특성 11, 보스 6 + 황금 돼지, 영웅 13(히든 2, Lv 30), 연구 11, 아이템 12, 소모품 5, 퀘스트 22.
- **화면**: 워크3 그대로 — 위 자원 바(골드·목재·식량), 아래 콘솔(미니맵·초상화·정보창·4×3 명령 카드 + 툴팁, 단축키 Q W E R / A S D F / Z X C V).
- **데이터 표**: `CFG`, `DIFFS`, `UPKEEP`, `TRAITS`, `BOSSES`, `OPT_LINES`, `RES`, `ITEMS`, `CONSUMABLES`, `QUESTS`, `PATH`.
- **원작 수치와 지어낸 수치가 섞여 있다.** README 의 "원작과 다른 점"에 구분되어 있다. 원작 확인 수치(예: 돈타워 2단 152, 놀이방 17~25)는 함부로 바꾸지 않는다. 대표님이 원작 규칙을 알려 주면 그쪽이 우선.
- **밸런스**: 바꾸면 자동 플레이(봇)로 도달 라운드를 재서 근거를 보인다.

### 🧱 극한 벽짓고 살아남기 (`Wall-Defense/`)

**한 줄**: 스타크래프트2 유즈맵 '극한 벽짓고 살아남기'를 참고한 싱글 생존 디펜스. 벽을 쌓고 넥서스를 100웨이브 동안 지킨다.

- **규칙**: 30초마다 웨이브, 총 100웨이브(최종 보스 케리건 처치 시 승리, 무한 모드 있음). 둥지가 정해진 웨이브마다 열린다. 적은 "거리 + 벽 체력"이 가장 싼 길로 약한 입구를 노린다(비행 적은 벽을 넘고, 땅굴벌레는 땅속으로). 적 300마리 누적 시 폭주 괴수.
- **콘텐츠**: 맵 3(협곡·십자로·평원), 난이도 4(쉬움~악몽), 사령관 5(H 능력), 변이원 12, 건물 19(1~3단계 강화), 유닛 17 + 영웅(레벨업·스킬), 테크 10, 업그레이드 13, 능력 6, 적 19 + 정예, 보스 10(고유 패턴) + 중간 보스 5, 이벤트 10, 유물 26, 보너스 목표 3종, 보급 상자, 영구 강화(사이오닉 정수)·업적 27, 통계 탭.
- **데이터 표**: `DIFF`, `CFG`, `BLD`, `UNITS`, `HEROES`, `TECH`, `UPS`, `ABIL`, `ENEMY`, `BOSSES`, `MINIBOSSES`, `EVENTS`, `RELICS`, `COMMANDERS`, `MUTATORS`, `OBJECTIVES`, `ACH`, `MAPS`.
- **밸런스 도구**: `tools/balance-bot.js` — index.html 을 연 브라우저 콘솔에 **이 파일 내용을 먼저 붙여 넣고** `runBot(101, { diff: 'normal' })` 실행 → 결과는 `window._r`. 협곡 맵 전용 단순 봇, 기준 기록 **보통 67웨이브**. 한 번에 돌리면 오래 걸리니 나눠서 실행한다.
- **알려진 함정**
  - 경로 비용 배열은 **`Float64Array`** 여야 한다 (Float32 로 바꿨다가 반올림 때문에 길찾기가 폭주한 적 있음).
  - 재생 적은 **2초 동안 안 맞았을 때만** 재생한다 ('거대 바퀴' 무적 버그 수정).
  - 첫 캐논은 벽 바로 뒤에 두어야 초반을 버틴다 (봇·밸런스 판단 시 참고).
- 영상에서 확인한 요소와 지어낸 세부 수치는 README "밸런스"에 구분되어 있다.

### 🎮 Game Hub (이 폴더)

## 3. 대표님이 일하는 방식 (지금까지의 작업에서)

- **콘텐츠를 크게 늘리는 걸 좋아한다.** "컨텐츠가 너무 없다, 4배로", "더 확장해줘"가 여러 번 있었다. 확장할 때는 개수(표)를 정리해 README 에 남긴다.
- **참고 원작이 있으면 원작에 가깝게.** 영상·자료로 확인한 것과 지어낸 것을 README 에 구분해 둔다.
- **수치를 바꾸면 근거를 보인다.** 봇 결과(도달 웨이브), DPS 비교표 등.
- **질문은 짧게 한 줄로.** 긴 선택지 목록보다 짧은 질문을 선호한다.
- **엔진·라이브러리를 새로 들이지 않는다.** 단일 HTML 구조를 유지한다 (필요하면 먼저 CEO 에게 묻는다).
- **코드를 바꾸면 그 게임의 `README.md`도 같이 고친다.**
- 예전에는 커밋 후 바로 GitHub 에 올렸지만, **지금 회사에서는 직원은 로컬 커밋까지만** 한다. 올리는 일은 CEO 지시로 기획경영부 `server-admin`이 한다.
