# 허브 — 신규 유저 안내 배너 · 공통 뱃지 10개 검증

- 검증일: 2026-10-27
- 검증자: `gamehub-qa-functional`
- 대상 파일: `GameHub/index.html` (로컬 커밋 `de81202` "허브에 신규 유저 안내 배너와 공통 뱃지 10개 추가")
- 근거 문서: `GameHub/README.md`("안내 배너·허브 공통 뱃지" 절), 배경 지시문의 세이브 구조 설명
- 방법: 브라우저 없이 `<script>` 내용을 추출해 Node.js(v24)로 최소 `document`/`localStorage` 스텁을 만들어 9개 시나리오를 실행·대조. `node tools/sync.js --check`로 games/ 사본 영향 없음도 확인.

## 결론: **부분 통과 — 치명적 문제 없음, 사소한 HTML 이스케이프 버그 1건**

핵심 금지선(게임 저장 키 4개 쓰기 금지, 자정 경계, 벽짓살 임무 배열 구분, 옛 세이브 호환)은 전부 통과했다. 다만 뱃지 10개 중 "퇴직금 보유" 뱃지의 툴팁 문구에 이스케이프 안 된 따옴표가 들어가 있어 HTML 속성이 깨진다(2번 항목). 기능(금색 켜짐 여부)에는 영향 없고 툴팁 텍스트만 깨지므로 치명도는 낮다.

## 확인한 항목

### 1. 문법 검사 — 통과
`<script>` 내용(11,190자, 1개)을 `new Function(document, localStorage, code)`로 파싱·실행. 9개 시나리오 전부 파싱 에러 없이 끝까지 실행됨(아래 2~5번 시나리오 목록).

### 2. 배너 로직 — 통과
- `noRecordAtAll`(317행)이 `GAMES.every(g => !g.record())`로 4개 게임 `record()`가 전부 falsy일 때만 true가 됨을 확인.
- 저장 데이터 전혀 없는 상태(시나리오 "완전 신규")에서 배너 노출 확인(`#firstBanner` 생성됨), 닫기 버튼 클릭 시 `gamehub.ui.v1`에 `{"bannerDismissed":true}` 기록 후 배너 DOM이 비워짐(`$('banner').innerHTML=''`, 327행) 확인.
- `gamehub.ui.v1`에 이미 `{bannerDismissed:true}`가 있는 상태(게임 기록은 없음)에서는 배너가 뜨지 않음 확인.
- **게임 저장 키 쓰기 금지 확인(가장 중요)**: `index.html` 전체에서 `localStorage.setItem` 호출은 268행(`read`, get만)·312행(`readHubUi`, get만)·**315행 단 한 곳**(`writeHubUi`)뿐이고, 315행은 `HUB_UI_KEY`(`gamehub.ui.v1`) 외 다른 키를 쓰지 않는다. 9개 시나리오 전체에서 `setItem` 호출 로그를 수집한 결과 `gamehub.ui.v1` 외의 키(슬라임/넥서스/머니/벽짓살 4개)에 대한 쓰기는 **한 번도 발생하지 않음**을 확인.

### 3. 뱃지 10개 조건 — 통과 (1건 표시 버그, 아래 2번 "실패" 참고)
10개 뱃지 조건을 모두 게임 기록 풀 세트(올라운더 조건 등 충족)로 테스트했고, 기대한 뱃지가 모두 켜짐을 확인.

| 뱃지 | 코드 조건(줄) | 결과 |
|---|---|---|
| 올라운더 | `played === 4` (360행) | 통과 |
| 탐험가 | `played >= 2` (361행) | 통과 |
| 슬라임 10레벨 | `(+slime.level\|\|0)>=10` (362행) | 통과 |
| 넥서스 웨이브100 | `(+nx.best\|\|0)>=100` (363행) | 통과 |
| 머니 라운드50 | `moneyBest>=50`, `moneyBest`는 record()와 동일한 `Math.max(...md.best 값들)` (364행, 299행) | 통과 |
| 벽짓살 웨이브50 | `wallBest>=50`, record()와 동일 계산(365행, 300~302행) | 통과 |
| 연속접속3일/7일 | `maxStreak`가 슬라임·넥서스·머니·**벽짓살(wallMeta.daily.streak) 포함** 4개 중 최댓값 (351~356행) | 통과 — 벽짓살만 streak=7인 시나리오로 별도 확인, 벽짓살이 빠지지 않음 |
| 오늘의 임무 올클리어 | `todayAllMissionsDone`, 날짜 일치 + `missionsAllClaimed` (344~357행) | 통과 (4번 항목에서 상세) |
| 퇴직금 보유 | `(+((md.meta\|\|{}).points)\|\|0)>0` (369행) | **조건 자체는 통과(정확히 켜짐)**, 단 툴팁 HTML이 깨짐 — 아래 "실패" 참고 |

**벽짓살 임무 완료 판정 버그 여부**: `missionsAllClaimed(daily, wallStyle)`(337~343행)에서 `wallStyle=true`일 때는 `daily.claimed`(별도 bool 배열)만 보고, `daily.missions[i].claimed`는 보지 않는다. 실제 벽짓살 세이브 구조(`games/wall.html` 503행: `claimed:[false,false,false]`, `missions`에는 `claimed` 필드 없음)와 일치 — **배경 지시문이 우려한 "missions[i].claimed를 잘못 찾아 항상 false로 새는 버그"는 없음**. 반대로 `claimed` 배열 없이 `missions[i].claimed`만 있는 가짜 데이터로 테스트하면 의도대로 "미완료"로 안전하게 처리됨(예외 없음) — 벽짓살 실제 세이브에는 항상 `claimed` 배열이 있으므로 실전 영향 없음.

### 3-1. (실패) 퇴직금 보유 뱃지 — 툴팁 HTML 깨짐

- **문제**: `BADGES` 배열의 title 문자열에 이스케이프 안 된 큰따옴표가 들어가 있어, 렌더링된 `title="..."` 속성이 중간에서 끊긴다.
- **코드**: `index.html` 369행
  ```js
  { icon: '💎', name: '퇴직금 보유', cond: ..., title: '머니 디펜스 영구 재화 "퇴직금"을 보유' },
  ```
  374행에서 `title="${b.title}"`로 그대로 삽입.
- **재현**: 머니 디펜스 세이브에 `meta.points>0`을 넣고 허브를 열면 실제로 생성되는 HTML이 다음과 같이 깨짐(Node로 재현한 실제 출력):
  ```html
  <span class="badge on" title="머니 디펜스 영구 재화 "퇴직금"을 보유">💎 퇴직금 보유</span>
  ```
  `title="` 뒤 첫 `"`(재화 바로 뒤)에서 속성값이 끝나버려 브라우저가 이 지점에서 `title` 속성을 닫고, 남은 `퇴직금"을 보유"` 텍스트를 잘못된 속성 토큰으로 처리한다. 결과적으로 마우스를 올려도 툴팁이 "머니 디펜스 영구 재화 "까지만 보이거나 비정상적으로 보일 수 있다(브라우저로 직접 확인은 못 했으나, HTML 속성 파싱 규칙상 확정적으로 잘림).
- **영향 범위**: 금색 켜짐(`.badge.on`, `class` 속성)과 뱃지 판정 로직 자체는 영향 없음 — **기능적으로는 정상, 툴팁 텍스트(UX)만 깨짐**. 다른 9개 뱃지의 title에는 따옴표가 없어 문제없음.
- **심각도**: 낮음(사소/코스메틱). 치명적이지 않지만 사용자에게 보이는 텍스트가 깨지므로 수정 권장.
- **제안**: `title`에 큰따옴표 대신 작은따옴표나 「」 같은 괄호를 쓰거나, 삽입할 때 `b.title.replace(/"/g, '&quot;')`로 이스케이프.

### 4. 날짜 경계(자정) 처리 — 통과
- `todayStr()`(332~336행)은 `new Date()`의 `getFullYear()/getMonth()/getDate()`(로컬 시간대 메서드)로 `YYYY-MM-DD`(2자리 패딩)를 만든다.
- 실제 게임 4개의 날짜 생성 코드를 대조:
  - `games/slime.html` 1993~1994행, `games/nexus.html` 1978~1979행·6610행: 동일하게 `getFullYear()/getMonth()+1/getDate()` + `padStart(2,'0')`로 `YYYY-MM-DD` 생성.
  - `games/money.html` 653행: 동일 방식.
  - `games/wall.html` 471행(`localDateStr`): 동일 방식, `daily.day`에 저장.
  - → 허브와 4개 게임이 **같은 로컬 날짜·같은 포맷**을 쓰므로 형식 불일치는 없음.
- 자정 경계 시나리오: 슬라임 `daily.date`를 "어제" 날짜로, 임무 3개를 모두 `claimed:true`로 채운 가짜 데이터로 테스트 → `todayAllMissionsDone`이 **false**로 정확히 계산됨(연속접속 뱃지만 켜지고 "오늘의 임무 올클리어"는 꺼짐). 자정을 넘기면 어제 날짜의 daily 블록이 더 이상 "오늘 올클리어"로 인정되지 않는 것을 코드 실행으로 확인.

### 5. 기존 세이브 호환성(옛 세이브) — 통과
`daily` 필드와 `meta` 필드가 전혀 없는 옛 세이브 형태(4개 게임 모두)로 돌려도 예외 없이 끝까지 실행되고, 관련 뱃지(슬라임10레벨 제외 — level은 있어서 정상 평가, 연속접속·오늘의임무·퇴직금)는 전부 "미획득"으로 안전하게 처리됨. 깨진 JSON 문자열(`'{this is not json'`)을 슬라임 키에 넣어도 `read()`의 `try/catch`(268행)가 null로 받아 처리하므로 예외 없음.

### 6. 모바일 375px — 코드 리뷰로 통과 (실제 렌더링 미확인)
- `.banner`(105~112행): `flex-wrap: wrap`, `justify-content: space-between`, 고정폭 없음. `.banner p`(113행)에 `flex:1; min-width:0;`이 있어 좁은 화면에서 텍스트가 줄바꿈/축소되며 가로 overflow를 유발하는 고정폭 요소 없음. `.banner .x`(115~116행)는 26×26px 고정이지만 닫기 버튼이라 문제 없음.
- `.badge-row`(125행): `display:flex; flex-wrap:wrap; justify-content:center; gap:8px` — 뱃지 10개가 375px에서 자연스럽게 여러 줄로 줄바꿈된다. `.badge`(126~131행)에 고정폭·`white-space:nowrap` 같은 overflow 유발 속성 없음.
- 단, 이 항목은 CSS 속성만 읽고 판단한 것이며 실제 브라우저 렌더링 확인은 못 했다 — **확인 필요(권장: `gamehub-qa-compat`가 375px 렌더링으로 재확인)**.
