## 확인한 항목 (지시받은 순서대로)

**1. 문법 검사** — `<script>` 전체를 추출해 `new Function(s)`로 파싱. 에러 없음 (길이 59,429자, 블록 1개, OK).

**2. 도감 보상에 배율이 안 걸리는지** — `dexRecord()`의 보상 코드:
```js
state.jelly += 30;                         // 최초 발견
if (e.kills === 10)  state.jelly += 80;
if (e.kills === 50)  state.jelly += 200;
if (e.kills === 200) { state.souls += 1; state.soulsTotal += 1; }
```
`jellyMult()`/`killJellyMult()`/`soulMult()`/`achMult()` 등 배율 함수 호출이 전혀 없다. 비교로, 일반 처치 보상은 `state.jelly += rewardOfStage(st) * killJellyMult();`(배율 적용)인데 도감 보상만 고정값 — 커밋 메시지·README 설명과 일치. **닫힌 고리 버그 없음.**

**3. 옛 세이브 호환** — `load()`의 병합 로직을 그대로 옮겨 Node로 두 가지 "옛 세이브"(① `dex`·`daily` 둘 다 없는 완전 구버전, ② `daily`는 있고 `dex`만 없는 직전 버전)와 깨진 JSON을 넣고 실행:
  - 둘 다 `state.dex = {}`로 안전하게 채워짐.
  - `state.ach`는 그대로 `{id: true}` 불리언 맵 유지(`target`/`cur`는 `ACHIEVEMENTS` 코드에만 있고 저장 데이터에는 안 들어감 — 포맷 영향 없음 확인).
  - `state.daily`, `state.lt`도 깨지지 않음. 깨진 JSON은 기존처럼 `catch`로 조용히 무시됨(크래시 없음).
  - 테스트 스크립트: 스크래치패드 `load_sim.js` (세션 임시 파일, 리포지토리에는 없음).

**4. 날짜 경계(자정)** — `git diff`에서 `ensureDaily`/`localDateKey`는 주석 한 줄(`// ensureDaily()가 날짜를 보고...`)에만 등장하고 실제 함수 바디는 이번 변경에 포함되지 않았다. **영향 없음.**

**5. 도감 완성률 계산** — `DEX_TOTAL = MONSTERS.length * TIERS.length`. 실제 배열 길이를 코드로 세어 `MONSTERS` 30개, `TIERS` 8개 → 240 확인. `dexCellsFilled()`의 비트마스크 집계 함수를 그대로 떼어내 "3종×일부 등급만 기록된 가상 상태"(종0: 2등급, 종1: 1등급, 종2: 1등급)로 실행 → 결과 4, 수동 계산(2+1+1)과 일치.
  - 몬스터/등급 인덱스 매핑도 확인: `dexRecord((st-1) % MONSTERS.length, tierOfStage(st))`이 기존 `monsterOf(s)`/`tierOfStage(s)` 공식과 정확히 같은 수식을 쓴다 — 도감에 기록되는 종·등급이 실제 잡은 몬스터와 어긋날 일 없음.

**6. 환생 시 도감 유지** — `rebirth()`에서 `const { soulUp, ach, lt, dex, autoFeed } = state;` → `state = freshState();` → `Object.assign(state, { souls, soulsTotal, soulUp, ach, lt, dex, autoFeed });`. `dex`가 업적(`ach`)·평생기록(`lt`)과 같은 자리에서 유지되고, 장비(`weapons`/`armors`/`trinkets`)처럼 초기화되는 목록에는 들어있지 않음. **의도대로 동작.**

**7. 모바일 375px** — 실제 브라우저로는 확인하지 못했고, 추가된 CSS 규칙만 읽어서 판단:
  - `.goals { display:flex; flex-wrap:wrap; gap:8px; }`, `.goal { flex:1 1 220px; min-width:0; overflow-wrap:break-word; }` — 220px짜리 2개가 375px 폭에 안 들어가면 `flex-wrap:wrap`으로 두 줄로 쌓이고, `min-width:0`+`overflow-wrap`으로 가로 넘침은 막힌다.
  - `.dex` 행은 `flex` + `.d-main { flex:1; min-width:0; }`(아이콘·보상 칸은 `flex:none`)이라 가운데 텍스트가 줄어들며 비슷하게 넘침 방지. `.dexlist { overflow-y:auto; }`로 세로 스크롤.
  - 다만 이번 변경에서 기존 `@media (max-width: 760px)` 블록에 `.goal`/`.dex` 관련 보정은 추가되지 않았다(다른 요소들처럼 폰트 축소 등은 없음). 정적 분석으로는 넘침 위험을 못 찾았지만, **실제 기기/브라우저 확인은 `gamehub-qa-compat` 담당**이라 그쪽 확인을 권한다.

**8. 몬스터 설명 대조** — `MONSTERS[].desc` 30개 전부를 `시나리오/2026-10-27_슬라임_몬스터도감_설명.md` 1~30번과 대조 → 이름·순서·문장이 전부 동일(예: 1. 들쥐 "곳간을 몰래 축내는 작은 말썽꾼", 19. 리치 "죽음을 다스리며 뼈의 군대를 부리는 자", 30. 별의 수호자 "별빛으로 이 층을 지키는 마지막 수호자" 등). **불일치 없음.**
