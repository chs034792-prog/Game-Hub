# QA 호환성 검증 — 용병단 키우기 허브 연결 (2026-11-02)

- 검증자: `gamehub-qa-compat`
- 대상: 원본 `GameHub/Mercenary-Idle/index.html`, 허브 사본 `GameHub/games/merc.html`, `index.html`(id:'merc'), `play.html?game=merc`, `sw.js`(gamehub-v2→v3), `manifest.webmanifest`
- 결론: **통과** — CEO 1순위 지시인 "휴대폰 세로 화면 + 탭만으로 조작"은 코드 검토·캡처 모두에서 문제를 찾지 못했다. 끌기·스와이프·두 손가락·길게 누르기로만 되는 기능도 없다.

## 검증 환경

- 로컬 서버: `python -m http.server 8795` (8790·8791 안 씀). 테스트 종료 후 프로세스는 셸과 함께 종료됨 — 현재 8795는 떠 있지 않음.
- 캡처 도구: Edge 헤드리스 CDP 스크린샷 (`mobile_shot.mjs`), `Emulation.setDeviceMetricsOverride`로 터치 에뮬레이션 포함.
- **참고(자동화 한계)**: 캡처 스크립트는 실제 손가락 터치가 아니라 `element.click()`로 클릭 이벤트를 발생시켜 동작을 확인했다. 코드에 `touchstart`/`touchmove`/`pointerdown` 등 터치 전용 핸들러가 없음을 grep으로 먼저 확인했으므로 클릭 이벤트 결과가 실제 탭 동작과 같다고 볼 수 있지만, **실기기(삼성 갤럭시 등) 터치 확인은 아직 못했다 — 확인 필요**.

## 1. 코드 검토 — 끌기·스와이프·전용 조작 여부

`Mercenary-Idle/index.html` 전체(1419줄)에서 `touchstart|touchmove|touchend|pointerdown|pointermove|mousedown|mousemove|dragstart|longpress|contextmenu|wheel|swipe` 를 grep — **0건**. 상호작용은 전부 `<button>` 요소 + `click` 리스너(13곳) 혹은 `data-action`/`data-tab` 위임 클릭이다. 탭만으로 모든 기능(전투 관전, 필살기, 파티 편성, 강화, 소환, 임무, 도감)에 닿는다는 뜻 — 극한 벽짓고 살아남기 때 재발한 "끌기 전용 조작" 문제는 없다.

## 2. 휴대폰 세로 412×915 (주 타겟)

캡처: `01_hub_portrait_412x915.png`(허브 카드), `02_merc_entry_portrait_412x915.png`(진입 직후, 튜토리얼 1단계), `03_merc_battle_portrait_412x915.png`(전투 화면, 튜토리얼 닫은 뒤), `04_tab_{party,enhance,summon,mission,codex}_412x915.png`(탭 5개), `07_hub_merc_card_412x915.png`(허브 카드 스크롤).

- 하단 탭바(파티/강화/소환/임무/도감) 5개 버튼이 화면 안에 전부 들어오고 잘리지 않는다. 아이콘 20px + 텍스트 11px, 버튼 높이 58px로 터치하기 충분한 크기.
- 필살기 원형 버튼(92×92px)이 탭바 위, 전투 로그 아래에 겹침 없이 떠 있다. 쿨다운 완료 시 금색 펄스 애니메이션으로 눈에 띔(03번 캡처).
- 각 패널(파티 편성/강화/소환/임무·출석/도감)은 화면 하단에서 올라오는 바텀시트(최대 높이 82%)로, 버튼·글씨가 겹치거나 잘리는 곳이 없다. 닫기(X) 버튼 44px 터치영역.
- 허브 카드(`index.html`)에 용병단 키우기 카드가 4번째로 정상 표시, 설명·장르 태그·기록 영역·플레이 버튼 모두 다른 3개 게임과 같은 스타일로 렌더링됨.
- play.html 상단 38px 띠가 게임 화면을 가리지 않음 — 게임 자체 상단바(스테이지/골드/표시줄)는 그 아래부터 시작.

**경미한 관찰(버그 아님)**: 전투 화면에서 로그 박스와 필살기 버튼 사이에 빈 공간이 큼(03번 캡처, 약 450px 높이의 여백). 기능상 문제는 없으나 시각적으로 허전함 — 기능 검증(`gamehub-qa-functional`)이나 아트팀 참고용으로만 남김.

## 3. 휴대폰 가로 915×412

캡처: `05_merc_landscape_915x412.png`.

- 가로로 돌려도 레이아웃이 깨지지 않는다. `#app`이 `max-width:480px`로 고정된 세로 패널을 유지하고, 좌우는 빈 배경으로 처리된다(아래 PC 항목과 같은 방식). 별도의 "세로로 돌려주세요" 안내는 없지만, 안내가 필요할 정도로 깨지지도 않는다 — 탭바·필살기 버튼·전투 UI 모두 온전히 보이고 눌림.
- `play.html`의 "전체화면" 버튼은 `@media (max-width:480px)`에서만 숨는데, 915px 가로 폭에서는 보임 — 의도된 동작(좁은 폭에서만 숨김).

## 4. PC 1600×900

캡처: `06_merc_pc_1600x900.png`(진입), `08_hub_pc_1600x900.png`(허브 2×2 카드 그리드), `09_pc_click_test.png`(클릭 기능 확인).

- 게임이 화면 가운데에 세로 폭(480px)으로 떠 있고, 좌우는 어두운 배경으로 자연스럽게 채워진다. 잘리거나 가로로 늘어나지 않는다.
- 마우스 클릭 동작 확인: 튜토리얼 `다음` 버튼 4회 클릭 → 정상 진행, **필살기 버튼 클릭 → 전투 로그에 "★필살기(직접 발동)★ 잔해들개에게 74 피해!" 기록되어 실제 발동 확인**(09번 캡처 로그), 강화 탭 클릭 → 패널 정상 오픈(무기 강화·레벨업 버튼·보유 재료 모두 렌더링). 코드에 터치 전용 핸들러가 없으므로 탭바·소환 버튼도 같은 방식(`click` 리스너)으로 동작할 것으로 판단.
- 허브 카드 그리드: PC 폭에서 2열로 배치, 용병단 키우기 카드가 머니 디펜스 옆(4번째 자리)에 겹침 없이 표시.

## 5. 다른 게임(슬라임·넥서스·머니) 회귀 확인

- `node tools/sync.js --check` 결과: **슬라임/넥서스/머니/용병단 4개 전부 "그대로" — 원본과 사본 100% 일치, 다른 게임 0개.**
- `play.html?game=slime|nexus|money` 각각 412×915로 열어 확인 — 세 게임 모두 정상 타이틀로 로드, 레이아웃 깨짐 없음(`10_other_slime/nexus/money_412x915.png`).
- `sw.js`가 `gamehub-v2`→`gamehub-v3`로 바뀌고 `CORE` 목록에 `./games/merc.html`이 추가된 것 확인. 캐시 이름이 바뀌면 활성화 시 이전 캐시(`gamehub-v2`)를 지우는 로직(`activate` 핸들러)이 있어 구버전 캐시가 남지 않는다.
- `index.html`·`play.html`의 `GAMES` 목록, `tools/sync.js`의 `GAMES` 표 — 3곳 모두 `merc` 항목이 일관되게 들어가 있고, `wall`(극한 벽짓고 살아남기)은 README의 2026-11-02 하차 결정대로 3곳 모두에서 빠져 있음. `manifest.webmanifest`의 shortcuts에서도 `wall`이 빠지고 `merc`가 들어감 — 일치.

## 7. 저장 공간(origin)·file:// 확인

- 새 저장 키 `gamehub.idlerpg.v1` — `index.html`의 `record()`가 `s.maxUnlockedStage`/`s.gold`/`s.battleWins`를 읽기만 하고 쓰지 않음(README 표와 일치).
- `file://`로 `play.html?game=merc`를 직접 열어본 결과(`11_file_protocol_merc.png`): 게임 자체는 정상 렌더링되지만, 최상위 문서에서 `iframe.contentDocument`가 `null`로 반환됨(Chromium이 `file://`에서 하위 리소스마다 별도 출처를 주기 때문) — 이 때문에 play.html의 `frame.contentWindow.focus()`가 조용히 실패할 수 있는데, 해당 호출은 이미 `try/catch`로 감싸져 있어 에러가 나지 않는다. 다만 이 환경에서는 iframe에 키보드 포커스가 안 갈 가능성이 있음 — README가 "file://에서는 저장 공간이 막혀 기록이 안 보일 수 있다"고 안내한 것과 같은 선상의 제약으로, 기존 3개 게임도 동일하게 적용되던 제약이라 이번 변경이 새로 만든 문제는 아님. `python -m http.server`로 열면(8795 기준) 이 문제가 없음을 위 1~4번 캡처로 확인했다.

## 확인·승인이 필요한 항목

1. **실기기 터치 테스트 요망** — 이 보고서는 헤드리스 브라우저의 터치 에뮬레이션 + `click()` 시뮬레이션 기반이다. 코드에 터치 전용 핸들러가 없어 실기기에서도 같은 결과가 나올 것으로 보이나, 대표님 갤럭시 S26 Ultra 실기기에서 한 번 더 확인을 권장한다(특히 필살기 원형 버튼의 탭 반응 민감도).
2. 전투 화면 하단 빈 여백(섹션 2 "경미한 관찰")은 버그가 아니라 UX 참고 사항이므로 팀장 판단에 맡긴다.
